# Shower Redemption Plan

**热水费救赎计划** —— 一个基于微信小程序的**蓝牙控水器直连工具**。通过 BLE 直接连接校园/宿舍热水控水器，绕过官方 App，实现设备扫描、扫码连接、开阀取水、关阀结算以及用水量与实际费用的本地计算。

> [!IMPORTANT]
> **计费窗口仅在本地展示，不产生任何实际扣费。** 页面上弹出的「本次消费」金额，是小程序读取设备回传的用水量后**在本地换算出的参考数值，只用于给用户自己查看**，不会触发任何扣款、划账或账户余额变动。真实的水费结算仍由学校 / 物业的水控系统独立完成，本工具既不参与该过程，也无法对其产生任何影响。

> [!NOTE]
> 本项目仅用于个人学习 BLE 通信协议与硬件交互原理，请在使用前阅读文末的[免责声明](#免责声明)。

## 功能特性

| 功能 | 说明 |
| --- | --- |
| 蓝牙扫描 | 扫描周边广播名称包含 `Wa` 的控水器设备，实时展示名称 / MAC / RSSI |
| 扫码连接 | 扫描设备二维码（10 位纯数字），解析出设备名后静默扫描并连接 |
| 快速重连 | 本地缓存上次连接的设备，一键直连并自动开阀 |
| 开阀取水 | 发送握手 + 开阀指令，等待设备回执后进入放水状态 |
| 关阀结算 | 发送关阀指令，解析设备回传的用水量并**在本地**换算出本次消费金额（仅供展示，不产生实际扣费） |
| 实时运行日志 | 页面内滚动的分级日志（INFO / SUCCESS / WARN / ERROR），便于排查 BLE 异常 |
| 自动清理 | 关阀结算后自动断开连接并释放蓝牙适配器与所有监听 |

## 使用说明

1. **连接设备**（三选一）
   - 点击「扫码/搜索设备」→ 选择「扫码」，扫描设备机身二维码；
   - 点击「扫码/搜索设备」→ 选择「搜索」，在设备列表中点击「连接」；
   - 点击「连接上次的设备」，从本地缓存直连并**自动开阀**。
2. **开阀取水**：点击「启动热水阀」，等待日志出现 `开阀成功！`。
3. **关阀结算**：点击「停止热水阀」，设备回传用水量后弹出本次消费金额，随后自动断开连接。该金额**由小程序在本地换算并展示，不会产生任何实际扣费**。

## BLE 通信协议说明

以下是本项目逆向整理出的通信流程，供学习参考。

### 1. 设备发现

- 广播名称前缀为 `Water`，代码中以 `Wa` 作为过滤关键字。
- 扫码得到 10 位数字（如 `1234567890`）时，设备名按 **后 6 位** 拼接，即 `Water567890`。

### 2. 服务与特征值定位

遍历设备所有服务，筛选 UUID 中包含 `0000f1f0` 的服务，再从中分别取出：

- **写特征**：具备 `write` 或 `writeNoResponse` 属性，用于下发指令；
- **通知特征**：具备 `notify` 或 `indicate` 属性，用于接收设备上报，需开启 `notifyBLECharacteristicValueChange`。

### 3. 指令表（下行）

| 指令 | 字节序列 | 作用 |
| --- | --- | --- |
| B0 | `FE FE 09 B0 01 01 00 00` | 握手 |
| B2 | `FE FE 09 B2 01 XX XX 1B` | 开阀（`XX XX` 为设备密钥） |
| B3 | `FE FE 09 B3 00 00` | 关阀，设备将回传本次用水量 |
| B4 | `FE FE 09 B4 00 00` | 结算确认 |

### 4. 设备密钥算法

设备名中的数字取**最后 6 位**（不足补前导 `0`），对每一位查表后与基准值 `0x2BDC` 依次异或，得到 4 位十六进制密钥：

```js
key = 0x2BDC
    ^ ONES[d[5]]   // 个位
    ^ TENS[d[4]]   // 十位
    ^ HUNS[d[3]]   // 百位
    ^ THOU[d[2]]   // 千位
    ^ TTHO[d[1]];  // 万位
```

查表数据见 `utils/calc.js` 中的 `ONES` / `TENS` / `HUNS` / `THOU` / `TTHO`。

### 5. 设备上报（上行）

设备上报帧以 `FDFD` 开头，代码通过 `indexOf("FDFD")` 定位帧头后按偏移解析：

- 第 6–8 个十六进制字符为指令码（`B0` / `B1` / `B2` / `B3`）；
- **B3 帧**长度不小于 40 字符时，第 34–40 个字符为本轮用水量（3 字节小端）。

指令下发后通过 `_waitForCmd()` 阻塞等待对应回执（握手 5s、开阀/关阀 10s），**超时不抛异常**，仅记录告警并继续后续流程，避免因设备静默导致流程中断。

### 6. 用水量与费用计算

```js
// 3 字节小端转大端后取整
const qty = parseInt(hex.slice(4, 6) + hex.slice(2, 4) + hex.slice(0, 2), 16);

// 单价默认 25 元/吨，qty 以 0.1L 为计数单位
const cost = Math.round(unitPrice * (qty / 10) / 1000 * 100) / 100;
```

即 `10000` 个计数单位 = 1 吨水。`calcCost()` 支持传入自定义单价（`unitPrice`），默认 `25`。

> **注意**：这里的计算完全发生在小程序本地，结果只通过弹窗展示给用户，**不会产生任何实际扣费**，也不会与运营方的计费系统发生任何数据交互。

### 7. 流程时序

```
开阀：B0 握手(5s)  →  B2 开阀(10s)  →  标记 valveOpen
关阀：B3 关阀(10s)  →  解析 waterHex  →  本地计算费用  →  B4 确认  →  本地弹窗展示(不产生实际扣费)  →  断开连接
```

## 常见问题

**扫描不到设备？**
确认手机蓝牙已开启；安卓机型需授予位置权限；设备处于唤醒状态且未被官方 App 或其他手机占用。

**连接成功但开阀失败？**
多为无法从设备名解析出水号所致，请检查设备名是否为 `Water` + 6 位数字的标准格式。

**关阀后金额为 0？**
设备未在 10s 内回传 B3 帧，或帧长不足 40 字符导致用水量解析失败，日志中会提示 `收到 B3 响应但无法解析用水量`。

**B2 开阀指令中的密钥从何而来？**
由设备名中的数字经查表异或推导，不同水号的密钥不同，见上文「设备密钥算法」。
